🚀 Руководство по установке и запуску Nexus IDE
Nexus — это не просто расширение, это полноценная среда разработки на базе Code-OSS, где ИИ-агенты интегрированы на уровне файловой системы и компилятора.

Требования к системе (Prerequisites)
Перед началом убедитесь, что у вас установлены:

Node.js: версия 18.0.0 или выше (рекомендуется v20 LTS).

npm: версия 9.0.0 или выше.

Git: для клонирования ядра Code-OSS.

API Ключ Anthropic: (на данный момент ядро AnthropicGateway использует модели Claude, например, Sonnet 3.5/3.7).

Шаг 1: Установка базовых зависимостей
Склонируйте ваш репозиторий и установите пакеты для всех воркспейсов (core, agents, agent-ts).

Bash

git clone https://github.com/BeSl/Nexus-AI-First-IDE.git
cd Nexus-AI-First-IDE
npm install
Шаг 2: Сборка хост-среды (Code-OSS)
Nexus работает поверх форка VS Code (Code-OSS). Чтобы система могла перехватывать UI и управлять файлами, необходимо скачать исходники редактора и применить ваши патчи.

Bash

# 1. Скачиваем ядро Code-OSS (около 700 МБ)
npm run vscode:clone

# 2. Применяем патчи Nexus (интеграция VFS и удаление телеметрии)
npm run patch:apply
Шаг 3: Настройка окружения
Создайте файл .env в корне проекта для подключения AI-провайдера:

Bash

# Файл .env
ANTHROPIC_API_KEY=sk-ant-вашки-ключ-здесь
# Если в будущем добавится Gemini или локальные модели, ключи будут здесь
Шаг 4: Проверка ядра (Sanity Check)
Прежде чем запускать IDE, убедитесь, что оркестратор и виртуальная файловая система (VFS) работают корректно на вашей машине.

Bash

npm test
Убедитесь, что все 94 теста XState машины и Skeleton Provider горят зеленым.

Шаг 5: Запуск IDE
Соберите TypeScript-код агентов и запустите среду разработки:

Bash

npm run build
npm run dev
Откроется кастомизированное окно редактора — это и есть ваша новая рабочая среда.

🧠 Как пользоваться Nexus (Рабочий процесс)
В отличие от обычного редактора, где вы сразу пишете код, в Nexus вы работаете как Технический Директор (CTO).

1. Формирование намерения (Intent)
Откройте панель Nexus (обычно вызывается через командную палитру или боковое меню) и введите задачу на естественном языке.

Пример: «Создай сервис для расчета налогов корзины товаров согласно правилам agent-ts».

2. Фаза Архитектора (Architect State)
Система не начнет писать реализацию. Сначала Architect Agent проанализирует проект через SkeletonProvider и предложит интерфейсы (контракты) и типы данных.

Ваше действие: Вы проверяете предложенные типы (*.types.ts). Если всё логично — нажимаете Approve. Если нет — отправляете на доработку.

3. Фаза Разработки и Теневой Сборки (Coder & Shadow Build)
После вашего апрува в дело вступает Coder Agent.

Он пишет код в Виртуальной Файловой Системе (InMemoryVFS).

Nexus запускает Shadow Build в папке ~/.nexus/shadow-build/.

Если код содержит ошибки TypeScript, агент получает лог ошибки и исправляет себя сам, не отвлекая вас.

4. Ревью и Применение (Reviewer & Done)
Когда сборка и тесты (Tester Agent) проходят успешно, изменения переносятся из виртуальной памяти в реальные файлы вашего проекта. Вы видите чистый, работающий и протестированный результат.

скрипт для запуска в корне setup.sh

Как это использовать:
Сохрани файл setup.sh в корне проекта.

Сделай его исполняемым (это нужно для Linux/macOS):

Bash

chmod +x setup.sh
Запусти его:

Bash

./setup.sh
(Для пользователей Windows, использующих Git Bash или WSL, этот скрипт тоже отлично отработает).
